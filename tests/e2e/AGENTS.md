# AGENTS.md — tests/e2e

Playwright end-to-end smoke tests that launch the real Electron app (`_electron.launch({ args: ['.'] })`)
with a temp `MEOW_USER_DATA`. Run after `npm run build` via `npm run e2e`; single file:
`npx playwright test tests/e2e/<file>.spec.ts`.

## Key files

| File | Responsibility |
|---|---|
| `smoke.spec.ts` | App launches, sidebar/status-bar (incl. version), native chat panel sends a message, mode selector toggles build/plan, settings connects a provider + syncs models (its rem-derived paddings are asserted as a ratio against the live root font-size, since the base font is user-configurable). |
| `prompt.spec.ts` | Permission prompt: click allow, keyboard `1`, the prompt is the last row of the chat feed (a `.chat-feed-content` child, inside the feed's scroll region, not a composer child), and it does not overlap the composer. A long question grows the card past half the window instead of scrolling inside it (no `overflow-y` of its own, no sticky header — the feed owns the scrolling). Skipping a question closes the prompt. |
| `question-echo.spec.ts` | The `question` tool end to end: its mock LLM streams a real `tool_calls` turn (the other mocks only stream text), so the loop actually runs the tool, and the option the user picks is echoed into the feed as a user bubble **after** the question's tool row — live, and again after a relaunch (the stored order, not a live-only render). |
| `composer.spec.ts` | The composer is one card: the field on top and every control (add menu, model picker, variant picker, send) on a single bottom bar, inside the card's frame — the card is exactly border + padding + one line box + the bar, the round 2.25rem button sits in the bar's trailing slot and the footer row no longer carries any picker. The model picker's menu is portaled to `<body>` so a narrow pane never clips it. The field grows with its content, caps at 8 lines (then scrolls) and shrinks back when emptied; Send is disabled while the field is empty (whitespace is not content), enabled with text, and clears the field when clicked; Enter sends and Shift+Enter inserts a newline; while a turn runs the button is Stop with a `Processing...` placeholder and Enter still queues; editing a queued message (the queue row's pencil) swaps Stop for `Save edit`; the queue card's arrow (`send now`) aborts the running turn so the queued message becomes a user bubble immediately; removing a queued message that is being edited (or letting it drain into its own turn) ends edit mode, clears the composer and still sends the next message; Stop ends the turn and brings Send back. Copies `sidebar-sessions.spec.ts`'s gated mock LLM, which holds the response body open so a turn is genuinely in flight rather than raced. |
| `context-footer.spec.ts` | Context footer shows real token usage, persists across reload, resets on new session; danger state past the auto-compact threshold (the panel then reads `(9% left)`); the readout is a 2rem (26px) ring button that opens the portaled `.context-panel` — summary rows, the stacked `.context-bar`, one total row per bucket (no drill-down rows) — with `aria-expanded` tracking the open state and `Escape` closing it. Every in-pane lookup goes through the file's `pane(window)` helper (`.pane-slot:not([hidden])`), because `SessionPanes` keeps the other sessions mounted; the panel itself is portaled to `<body>`, so it is looked up on `window`. |
| `chat-scrollbar.spec.ts` | Chat feed scroll: opening a session lands the feed at the bottom of its window (`waitForHeightSettle` first, so the app's ~60-frame pin loop can't make a mid-settle read look correct), paging the whole transcript in via the top edge then reporting a real scrollHeight (no content-visibility collapse), and the new-turn anchor at the 20px inset holding under manual scroll and reduced motion (`anchorTop` measures from inside the feed, since the optimistic row is replaced once the transcript reloads). |
| `sidebar-sessions.spec.ts` | Sidebar session rows: create via the project row `+`, switching does not stop a running session (exactly one pane visible), status dot idle/running/waiting, delete via the row menu; also the title bar's session dot + name and icon-button geometry (`.icon-btn` is 2rem square with a 0.25rem radius, asserted against the live root font-size). |
| `session-title.spec.ts` | The active session's title lives in the window title bar (there is no pane header row): with a long session name the name ellipsizes and the `⋮` stays inside the bar, left of the panel tools, and still receives its click; collapsing the sidebar shrinks the brand strip so the title sits next to the expand button. |
| `selectors.spec.ts` | Selector triggers and rows: the shared `.dropdown-caret` and its `aria-expanded`-driven rotation (0° closed, 180° open); a selected row is `--bg-active` with `border-left-width: 0` and a right-aligned `.menu-item-check` (flush against the row's rem-derived padding edge, 16px wide, reserved on unselected rows). VariantPicker and the ModelPicker's rows are unreachable with a bare `userData` (see the note in the file). |
| `git-panel.spec.ts` | The docked Git panel on a seeded repo with a bare remote: the status bar and the branch chip read `↑1`, the Changes tab shows the `Staged` / `Changes` groups and a file row expands to its diff in place, the History tab marks only the unpushed commit and expands a commit to its message + file list, then a file to that file's diff with a back row. A `git commit` made outside the UI and a new untracked file both appear without clicking Refresh (the panel's 2.5s poll). |
| `menus.spec.ts` | Dropdown menu visual language: shared metric set (32px rows, 10px container radius, `gap: 0`) across a sidebar menu and a picker; action menus carry 16px icons, `.menu-sep` dividers and the project path header; pickers are asserted leading-icon-free (row starts with `.menu-item-label`, never an icon) and separator-free. |
| `terminal.spec.ts` | Session terminal panel: toggle via keyboard shortcut (`Ctrl+\`` / `Cmd+\``), wait for initial tab and xterm screen, type `echo E2E_TERM`, assert row output, switch sessions and back to verify scrollback re-attach, close terminal tab. |
| `chat-command-box.spec.ts` | A `powershell` fence in a seeded assistant message renders as a command box (`.chat-cmd`: command text + `Run in terminal` / `Copy command`) while a `console` fence stays a plain `pre`; Copy puts the command on the clipboard (read back through Electron's `clipboard`); Run opens the session terminal panel with exactly one tab and the command's output (`meow-cmd-ok`) shows up in the xterm rows. |
| `files-panel.spec.ts` | Files panel layout: the file tree is the right-hand column (its left edge starts where the editor column ends), the filter carries the `Filter, or ? to search in files` placeholder, the per-file bar labels an open nested file by its project-relative path and spans the panel (right edge on the panel's inner edge, both columns starting below it), and Toggle file tree hides the tree — expanded folders survive the toggle because it is hidden, not unmounted — with the `localStorage` `meow.files.treeHidden` choice surviving closing and reopening the panel (the empty bar keeps the toggle reachable). Also file icons and git state in a real repo seeded with an isolated `-c user.name/-c user.email` identity: letters `M` and `U`, a dot on a changed directory, no decoration on `.git` or an ignored file, the letter still visible on a truncated long name, the code icon on the tree row and on its tab, a content-search hit keeping its own row layout behind its icon, a directory row with no folder icon whose chevron starts at the same x as a sibling file's icon (within 1px), and a non-zero border radius on the active row. Also preview tabs: click A then B leaves one italic preview (B), a double click opens permanent so a third click replaces only the preview, pinning moves a tab first and Close all tabs keeps it, and typing in a preview promotes it. Also the send-line gutter: it sits left of the line numbers, its `+` only becomes opaque on the hovered cell, and clicking it puts the fenced `path:line` block into the visible pane's `.chat-input-field`. |
| `panels-per-project.spec.ts` | Right-hand panels are per project folder: two seeded projects, Files opened in one is gone in the other and comes back on return (each folder's tree shows its own files, closing in one leaves the other open); the Git panel behaves the same, and the sidebar project menu's **Git** item activates that project before showing its panel. |

## Conventions

- Each test uses an isolated temp userData + temp project; writes `workspaces.json` directly.
- **Never hardcode a px metric that comes from a `rem` rule.** The root font-size is user-configurable
  (default 13px, CSS fallback 12px), so `2rem` is 26px, not 24px. Derive the expectation from the live
  root (`parseFloat(getComputedStyle(document.documentElement).fontSize)`) or from the element's own
  computed style, and compare with `toBeCloseTo(..., 0)` — a fractional sum rounded before arithmetic
  drifts by a pixel.
- **Requires `npm run build` first** — e2e launches the built app in `out/`.
- Use locator auto-wait (e.g. `toHaveText`/`toContainText`) for async UI (IPC round-trips, streaming).
- After touching IPC/UI, add/extend a smoke assertion so regressions are caught here.
- `playwright.config.ts` strips `ELECTRON_RENDERER_URL` / `NODE_ENV_ELECTRON_VITE` at load: the dev app
  exports them to its children, so a leaked value makes main load the vite dev server and the suite
  silently tests the current `src/` instead of the built `out/`.
