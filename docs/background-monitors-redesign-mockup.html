Design proposal · Meow desktop

Background sessions & Monitors — one expandable-list pattern

Both surfaces become the same object: a compact, status-first list where each row is a summary (state · elapsed · one hint) and clicking the row expands it in place to reveal content and the full action set. No horizontal pill strip, no separate detail column — the list keeps its position while a row opens, so nothing jumps and nothing is hidden behind a second pane.

01 Background sessions — bottom dock, accordion rows

Replaces the pill strip that currently sits under the panes. Collapsed it is one 2.1rem bar (2 running · 1 stopped + state dots). Expanded it grows upward to at most ~22rem and scrolls; the session panes keep their full width. Click a row to expand it; Open session is an explicit button so a click never steals focus by accident.

02 Monitors — accordion instead of master/detail

The current Monitors tab splits the panel into a list and a detail block below it, so a long list squeezes the detail to nothing. Here it is one list, grouped Waiting / Finished, and a row expands to show its facts, its result and its actions. The row that changes state keeps its place — a resolved watch stays under Waiting until the panel is reopened, so nothing jumps under the cursor.

Row anatomy — one shape for both lists

state dot label state chip elapsed / age caret

Collapsed: a single 2rem line, everything that changes at a glance. Expanded adds:

  • meta line — mode · model · project · short session id (mono, faint)
  • content block — last messages (session) or latest output / result (watch), clamped with a fade
  • action row — primary on the left, destructive pushed to the far right

State → treatment

Only running/watching pulses. An attention/error row also gets a 2px inset bar in yellow/red so a needs-input session is visible with the dock collapsed.

Action matrix

RowActions (expanded)
session · running / idleOpen session · Stop · Delete
session · stopped / exitedOpen transcript · Delete
monitor · watchingStop watching · Open output (shell) / Open sub-session (delegation)
monitor · resolvedDismiss · Open output / Open sub-session

Collapsed rows keep no buttons: the strip stays readable and the caret is the only affordance. Delete stays behind the existing ConfirmDialog.

Behaviour, motion, a11y

  • Single-open accordion per list; the open row keeps its id, so a push event never collapses it.
  • Row header is a real <button aria-expanded aria-controls>; the action row is a sibling, never nested inside it.
  • Height animates 160ms ease; caret rotates 90°. prefers-reduced-motion drops both.
  • Elapsed ticks once per second, only while a row is open — collapsed rows show a coarser “2h ago”.
  • Keyboard: Tab to a row, Enter/Space toggles, Esc closes the open row before the dock itself.
  • Live regions stay off for the ticker; only state transitions announce (polite) — “npm test matched”.

Nothing in this proposal requires a new channel. Optional later: a lastMessagePreview field on AgentState would let the collapsed row show one line of context without an extra round-trip.

Why this beats the two current shapes

  • Pill strip → dock: the strip has no room for state reasons or content, its three tiny buttons sit on every row, and it scrolls horizontally once there are more than ~3 sessions. The dock gives each row a line, keeps actions one click away, and stays a single bar when idle.
  • Master/detail → accordion: in a 22rem-wide panel the detail block is permanently starved; a long list means scrolling two regions. The accordion gives the selected watch the full panel width and the list never needs a second scroll container.
  • Same pattern twice means one component (ExpandableList + row slots), one set of states, one set of keyboard rules — and the chat's background-tasks card can reuse the row markup it already has.
