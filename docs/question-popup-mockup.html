Question popup — redesign mockup

Every state of the permission / question prompt after the four requested changes. Static mockup only — no app code has been changed. Review the cards, then pick the open decisions at the bottom.

What changes

1
Header “×” = skip Always visible on a question card, next to the collapse chevron. Esc does the same. Skip ends the turn (decided).
2
AI-labelled action buttons submitLabel, skipLabel, customLabel; at most two action buttons.
3
One action row No more body buttons + footer buttons duplicating the same action.
4
Text answer = input only No Send button beside the field. Enter submits; Esc / × skips.

State machine (footer rules)

options.length === 0 → [ input ] + hint “Enter to send · Esc to skip” (no buttons) options > 0, input open → [ input ] + hint “Enter to send · Esc to close input” (no buttons) options > 0, multiple, no input → [ option rows ] + [ Submit ] [ Skip ] (one row, Submit disabled until ≥ 1) options > 0, single, no input → [ option rows ] + [ Skip ] (one row; clicking a row answers immediately) collapsed → header only + one-line question + ×

Proposed AI labels

Keep options as the choice rows (their labels are already AI-provided). Add three optional labels for the chrome. The UI still renders at most two action buttons — Submit + Skip — and Skip always keeps its skip behaviour; the model can only rename it. 

// src/shared/types.ts — QuestionPrompt / prompt-request / PendingPromptInfo
question: string
header?: string
options?: QuestionOption[]
multiple?: boolean
custom?: boolean
submitLabel?: string   // confirm button, 1–3 words, max 24 chars (default: "Submit")
skipLabel?: string     // skip button, 1–3 words, max 24 chars (default: "Skip")
customLabel?: string   // free-text row, 1–4 words, max 24 chars (default: "Type your own answer")
// src/main/agent/tools/question.ts — schema additions
submitLabel: z.string().optional().describe('Label for the confirm button (1-3 words, max 24 chars). Default: Submit'),
skipLabel:   z.string().optional().describe('Label for the skip button (1-3 words, max 24 chars). Default: Skip'),
customLabel: z.string().optional().describe('Label for the free-text answer row (1-4 words). Default: Type your own answer')
FieldDefaultWhere it rendersBehaviour
submitLabelSubmitMulti-select action rowSubmits the checked rows (disabled while empty)
skipLabelSkipFooter skip + × tooltipAlways skip — never changes the action type
customLabelType your own answerLast option rowOpens the input-only answer field
options[].label—Choice rowsAlready AI-labelled; single-select answers on click

Sanitize every label in main: trim, collapse whitespace, cap at 24 chars, fall back to the default when empty. The two-button cap is structural — the renderer only has slots for Submit and Skip, so the model cannot add a third action.

Open decisions

1. What does × do? Decided: stop the turn. × and Skip both call stopChat, matching today’s Skip. The agent stops and the tool reports “user did not answer”.
2. Skip in the single-select footer? Keep the one-button [Skip] row, or rely on × / Esc only and leave the single-select footer as a hint line?
3. × on permission cards? Add it as a second Deny affordance, or keep permission prompts exactly as they are?
4. Cap the option count? Claude uses 2–4 options. Keep the current unlimited list, or cap it at 4 (plus the free-text row)?
5. Esc inside the input Close the input (back to the option list) or skip the whole question? Current mockup: close the input; × always skips.
6. Label source Three optional fields (submitLabel, skipLabel, customLabel) — or an explicit actions[] array? Fields are simpler and keep options backward-compatible.
