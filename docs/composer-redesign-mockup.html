4 Send now — behaviour

  • Click → on a queued row: that message is promoted to the head of the queue and the running turn is aborted, then the queue drains. Equivalent to Stop followed by an immediate send, but the message is not re-typed.
  • No click: unchanged. Non-deferred queued messages are steered into the running turn at its next loop step (takeSteers); anything left starts when the turn ends.
  • Wiring: new channel Channels.ChatQueueSendNow → window.api.sendQueuedNow(agentId, id) → main promotes the entry and calls stopAndDrain(). No change to stopChat or the queue cap.
  • Affordance: the arrow is only shown while a turn is running (when the queue can be waiting); with an idle agent the queue drains on its own. Tooltip: “Send now — interrupts the running turn”.
  • Keyboard: Alt+Enter in the composer sends the newest queued message now, so the mouse is optional.

5 Open questions

  • Queue placement — above the composer (this mockup) vs. staying as transcript rows. Above the composer keeps it attached to the input it will fill; in the transcript it scrolls away.
  • Project + branch chips — include them, or keep the footer to just mode + context? They need git status passed into ChatPanel (today only App holds it).
  • Context ring — footer (this mockup) or card bar? Footer keeps the bar to model / variant / send.
  • Send now semantics — interrupt the running turn (this mockup), or wait for the current step to finish and then send? Interrupt is what “không cần phải đợi” implies, but it can cut a tool call mid-flight.
  • Voice input — out of scope for this pass.
