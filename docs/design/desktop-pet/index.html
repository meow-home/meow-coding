4 · Notes

Why this reads as “Meow”

  • The head path is copied from the logo, not redrawn — no drift at any size.
  • Shape A keeps the logo face literally: the blue > is the eye, the orange _ is the mouth.
  • Shape B trades the chevron for two round eyes (friendlier, weaker brand read). Shape C puts the prompt inside a mini terminal window on the head.
  • Palette is locked to the logo: #1b1e23 shell, #3b8bf5 blue, #f7941d orange.

Motion rules

  • Nothing translates the whole pet except the host — moods animate the body box.
  • Squash and stretch around a fixed floor point (transform-origin 50% 88%).
  • Blink is a scaleY(0.1) on the eye group, 130 ms, every 2.2–6 s.
  • Ear twitch fires twice per 7.5 s cycle, one ear offset by half a period.
  • One-shots (happy, notify) revert to the previous mood.

If this ships as a real desktop pet

  • A second BrowserWindow: transparent: true, frame: false, alwaysOnTop, skipTaskbar, hasShadow: false, resizable: false.
  • Drag moves the window (setPosition); position persists per display in userData.
  • Click-through outside the pet silhouette: setIgnoreMouseEvents(true, { forward: true }) and flip it off over the body.
  • Moods map to app state: working, thinking, error, notify — no new IPC surface needed beyond one event channel.
  • The pet is decoration: it must never steal focus from the main window.

Decided

  • Shape B shipped: 30px, perched on the input card's top border, 7.5rem in from the right edge (src/renderer/src/components/chat/MeowPet.tsx).
  • Nine moods wired in the app: idle, look (hover), think (waiting for the first token), type (streaming), sleep (45 s idle), happy (done / click), notify (prompt / background turn), error (failed), drag (pointer down). Only walk / run stay unused.
  • No speech chip at this size — the text would be unreadable.
  • Open: light theme (keep the dark shell), and whether it should ever sleep.
