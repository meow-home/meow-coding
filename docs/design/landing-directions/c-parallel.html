Sessions

A session is a chat with the agent. It is also a process you can steer.

Create, rename, stop or delete a session from its own sidebar row. Push one to the background and it keeps working while you read another. Send a message mid-turn and it is injected at the next step, so you can redirect without killing the run.

Capabilities

Everything the parallel workflow needs, in the window.

Control

Permissions you set once, then forget

Per-tool allow, ask or deny with wildcard patterns. Remembered answers, a read-only plan mode, and a prompt that tells you exactly what is about to run.

Recovery

Undo a whole turn, files and transcript

Every turn snapshots the files it touched. Undo restores them and trims the conversation; redo puts both back. Nothing is lost to a bad edit.

Context

Compaction before the wall

Older turns are summarized with a verbatim tail kept intact, so a long session keeps its thread.

Cost

Tokens and dollars, per session

Priced from the models.dev catalog, cache reads included. Per model, per session, per day.

Agents

Subagents and delegation

Spawn an isolated agent with narrowed permissions, or hand the task to another session.

Also included

Hooks and memory · Files and Processes overlays · Browser bridge · Office documents · Background updates

Hooks run your own policy outside the context window. A per-project memory store keeps durable notes across sessions. The Files overlay searches a project by name and content; the Processes overlay shows every background shell with live output. The browser bridge drives a real Chrome profile through an approved extension.
