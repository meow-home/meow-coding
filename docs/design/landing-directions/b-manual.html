Name

meow-coding — run many coding sessions in one window

Synopsis

meow-coding [--project DIR] [--session NAME] [--theme dark|light]
meow-coding --new-session [--agent meow] [--model MODEL]
meow-coding --list-sessions            # every session, running or idle

One window. Every session keeps running — including the ones you are not looking at.

Most coding agents live in a terminal, one conversation per window. Meow Coding makes the session the unit of work instead: each one gets a pane, stays mounted, and keeps its own transcript, tool calls, permissions and cost. Nothing is a black box, because the agent is first-party and runs in the app.

Description

A session is a chat with the Meow agent. It reads and writes files, runs commands, searches the web, drives a browser, and asks before doing anything you have not allowed. Every turn snapshots the files it touched, so undo restores the files and trims the transcript together.

Sessions

--new-session
Start a session from the sidebar. It is titled automatically from your first message. Create, rename, stop, delete, or push to the background from the session's own row.
--background
Move a session out of view without stopping it. Background sessions appear in their own panel with live output, and raise an alert when they finish or fail.
--steer
Send a message while a turn is already running. It is queued and injected at the next step boundary, so you can redirect the work without killing it.
--compact
Summarize the older part of the transcript when the context limit approaches. A verbatim tail is kept intact, so the thread of the conversation survives. It also runs while the session is idle.
--undo / --redo
Step back or forward one turn. Files and transcript move together, from per-turn snapshots.
--plan-mode
Run read-only. The agent can look at everything and change nothing — for analysis and review.

Tools

Twenty-two tools ship with the agent. Each call appears in the transcript as a card you can open, so you can see exactly what ran and what it returned.

ToolKindDoes
bashshellRun a command; long jobs can go to the background and be read later
read · write · editfilesRead a file, create one, or apply a targeted edit
apply-patchfilesApply a unified diff across several files in one call
glob · grepsearchFind files by pattern, search their contents
gitvcsStatus, diff, log and commit without leaving the chat
todowriteplanKeep a task list visible in the pane header
questionplanAsk you to choose before committing to a direction
taskagentsSpawn an isolated subagent with its own context and narrowed permissions
delegate_sessionagentsHand a task to another session in the same project
skillagentsLoad a bundled or custom skill into the current turn
webfetch · websearchwebRead a page, or search for one
browserwebDrive a real Chrome profile: navigate, click, type, read
lspcodeAsk a language server for definitions, references and symbols
officedocsCreate and edit .docx, .xlsx and .pptx files
revertsafetyUndo the files this session changed

MCP servers add their own tools to the same list, over stdio or HTTP. A custom tool is a JavaScript module dropped into userData/tools.

Commands

Type / in the composer to run a command. Twenty ship with the app; the fifteen Superpowers workflows cover the long jobs — brainstorming, planning, executing, reviewing.

  • /initWrite or improve AGENTS.md for this project
  • /reviewReview the uncommitted changes
  • /newStart a new session
  • /compactSummarize older context to free space
  • /frontend-designDesign or redesign a UI
  • /brainstormingExplore intent before building
  • /writing-plansTurn a spec into a plan
  • /executing-plansWork through a plan
  • /test-driven-developmentTest first, then implement
  • /systematic-debuggingFind the cause before the fix
  • /requesting-code-reviewAsk for review with evidence
  • /verification-before-completionProve it works before claiming done

Write your own in Markdown. $1..$N takes arguments, @path inlines a file, !cmd inlines a command's output. Subagent roles live in .meow/agents/*.md and can only narrow what your permission rules already allow.

Files

meow.json
Providers, models, permissions, compaction thresholds, sampling overrides. Per project, at the repo root.
.meow/memory/
Durable notes the agent keeps across sessions. One Markdown file per fact, with an index the agent reads at the start of every turn.
.meow/agents/
Custom subagent roles for this project. Frontmatter takes a name, description, tool list, model, and deny/ask rules.
userData/workspaces.json
Your projects and their sessions.
userData/logs/
Every byte of agent output, one log per session, openable from the pane menu.

Settings

Nine tabs, and no config file you have to hand-edit. Hooks run your own policy outside the context window — PreToolUse, PostToolUse, Stop.

Sub-agents
