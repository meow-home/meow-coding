# AGENTS.md — src/main/agent

The native "Meow agent" core: the agent loop, LLM integration, config, sessions, permissions,
commands, references, compaction and usage accounting. Orchestrated by `MeowAgentManager` in
`src/main/meow-agent-manager.ts` (which lives one level up).

## Key files

| File | Responsibility |
|---|---|
| `loop.ts` | `SessionRunner`: the agent turn loop — streams LLM output, executes tool calls, handles permissions/aborts, emits `ChatEvent`s. `system` may be a function, re-resolved once per run. The heart of the agent. Per-turn <system-reminder> context (`turnContext` dep, resolved once per run) is prepended to LLM messages; tool results append reminders (git freshness after git/git-like bash, MEMORY.md sync after write/edit into the memory dir; a truncated answer (length/max_tokens, no tool call) resumes with a continuation nudge up to 3× per run then reports `done('length')`; each step runs through `createResponseGuard` (tool flood at 32, call → text → call, character-level repetition) and emits `step-start`; a repetition with no calls is discarded (`step-discarded`) and retried once with `antiRepetition`, other cuts keep the accepted calls and note the cut on the last result; calls are decided up front, run in model-order batches (`tool-scheduler.ts`), and appended by `finishCall`, where the per-run `toolLoopDetector` may attach a `[meow]` note; recoveries share `MAX_LOOP_BREAKS` (2) then report `done('stuck')` with `stuckCategory`; each step streams through its own `AbortController` chained to the run signal, so cutting a loop short actually cancels the provider request instead of merely stopping consumption; a refusal finish reports `done('refusal')`; thrown tool errors are formatted by `formatToolError`). |
| `background-process-store.ts` | `BackgroundProcessStore`: manages long-lived background shell processes started via `bash run_in_background`. Spawns process tree using `buildShellCommand`, holds an in-memory output buffer per process (ring buffer capped at 256 KB / 2000 lines), supports incremental reads (`readNew`), filtering, and process tree termination (`kill` via `tree-kill`). Limits per-agent concurrent processes (default 10). Extends `EventEmitter` and emits `data` (`BgDataEvent`) / `exit` (`BgExitEvent`) and exposes read-only `inspect(id)` for observers (the `monitor` tool), without touching the read offset. `list(agentId)` returns running + (not-yet-reaped) exited entries for the Processes overlay. `waitForNew(id, ms, signal)` resolves on unread output, exit, timeout, or abort and always removes its listeners. |
| `monitor-store.ts` | `MonitorStore`: async watches over background shells for the `monitor` tool. Subscribes to `BackgroundProcessStore` `data`/`exit` events per target and resolves on the first of regex-match / exit / timeout, calling `onResolve`. Foreground waits consume immediate/buffered resolutions atomically; expired/aborted waiters detach so a later resolution still follows the background notification path. `handleMonitorResolve` appends an assistant message, notifies, and auto-wakes the idle agent. Per-agent monitor limit (default 10); details capped at 500 chars. Each entry carries a human `until` summary (`/READY/ or exit or 30s`); `list(agentId)` returns active monitors for the Processes overlay. |
| `background-exit.ts` | `handleBackgroundExit`: exit completion handler when a background process terminates. Appends an assistant notification message to the originating session, sends a desktop notification, and wakes the agent if idle. |
| `poll-monitor-store.ts` | `PollMonitorStore`: deduplicated interval command watches with cancellable foreground `wait()` calls, waiter cleanup on pending/abort settlement, atomic resolution delivery, and bounded process cleanup. |
| `repetition.ts` | Degenerate loop detectors. `repeatDetector` flags a character-level tandem repeat at the tail of one streamed channel (any script; ignores separator-only units) and returns the raw length to keep; `toolLoopDetector.observe` reports `poll` (idle `bash_output`) or `repeat` when the same call + result recurs 3× in 8 completed calls. Both pure + unit-tested. |
| `response-guard.ts` | `createResponseGuard()` per step: `tool-flood` past `MAX_TOOL_CALLS_PER_RESPONSE` (32), `interleaved` on call → text → call, `repetition` from `repeatDetector` per channel; `textBeforeFirstCall()` bounds the text kept on a cut. |
| `tool-scheduler.ts` | `scheduleBatches` splits a response's calls, in model order, into batches (consecutive `concurrencySafe` + `allow` calls together, everything else alone); `runWithConcurrency` runs a batch with at most `MAX_TOOL_CONCURRENCY` (10) in flight. |
| `harness-note.ts` | `harnessNote` / `attachNote` / `cutNote` / `toolLoopNote`: the `<system-reminder>[meow] …` notes the loop attaches to a tool result — the only way it speaks to the model mid-turn (no synthetic user messages). |
| `tools/text-match.ts` | Pure exact-text matcher used by `edit`: preserves literal replacement boundaries and maps LF search strings onto unique CRLF file regions without relaxing whitespace. |
| `llm.ts` | `LlmClient` interface + `createLlm` factory (Anthropic / OpenAI-compatible); `classifyLlmError` + `withRetry` retry a stream that failed before emitting anything — rate limits retry up to 10 attempts, server (5xx)/socket errors are `unbounded` and keep retrying until the network/API recovers (or Stop); default sleep is `abortableSleep` (Stop interrupts a backoff/Retry-After immediately), `retryAfterMs` capped at `MAX_RETRY_AFTER_MS` (60s), and `onRetry` fires before each real retry so the UI can show "Retrying…"; `parseMaxTokensRejection` (number-only wrapper `reduceBudgetForMaxTokensError`) re-runs with a smaller budget when the provider rejects `max_tokens` (catalog overstates the model's real output limit; DeepSeek, OpenAI `at most M completion tokens` and Groq `must be less than or equal to M` formats), firing `onReducedBudget(realLimit)` so the learned-limits store can remember it — a vLLM context rejection re-runs with `context - prompt - 256` but is not learned (it fits that prompt only); `withCacheBreakpoints` breaks after the anchored summary. `formatLlmError` renders a thrown error for the UI: it unwraps RetryErrors and status/responseBody API errors, and rescues bare structured objects (`{ message, type, code }` SSE error chunks, nested `{ error: { message } }`) that would otherwise stringify as `[object Object]`. A bare SSE error chunk with no HTTP status but a rate-limit marker (`code`/`type`/`name` matching `/rate[-_ ]?limit/i`, e.g. `{ code: 'RATE_LIMIT' }`) is classified like a 429 — retryable and bounded. For opencode endpoints (provider id `opencode`/`opencode-go` or a baseUrl on `opencode.ai`), `createLlm` mints a per-client `ses_` session id and sends it as the `x-opencode-session` header — the Zen/Go gateway rejects requests that omit it. `createLlm` takes an optional 6th `sampling` argument (meow.json overrides) and sends `resolveSampling` params on the OpenAI-compatible branch; `LlmStreamOptions.antiRepetition` adds the retry penalty; SDK-invalid tool calls are yielded with `invalid`/`invalidReason`. |
| `message.ts` | `toLlmMessages`: converts stored transcript (user/assistant/tool items, incl. image parts) into AI-SDK model messages; filters out empty/invalid image attachments and omits empty text content parts when sending images to avoid LLM provider 400 errors; `keepFullTurns` exempts the recent tail from `toolOutputMaxChars`; `toToolDefinition` wraps tools. ToLlmOptions.turnContext prepends a per-turn <system-reminder> user message at transform time (never written to the store). A tool result with both output and error serializes as `error-text` carrying the partial output plus the error. Reasoning parts are replayed only for assistant messages after the last user message (the current tool loop); `toToolDefinition` has no `execute` (the SDK reports calls, the runner runs them). |
| `config.ts` | Loads `meow.json` + env; `MeowConfig` / `ResolvedAgentConfig`; `loadMeowConfig`, `resolveAgentConfig`, `settingsToConfig`/`configToSettings`, `writeMeowConfig`; defaults (tokens, compaction, notifications, lsp); `resolveOutputTokens` picks the per-answer output **reserve** (catalog/live/learned limit, hard cap, half-context guard, fallback `DEFAULT_MAX_OUTPUT_TOKENS`) — `maxContextTokens` is an optional override, `maxOutputTokens` is an optional override too; `resolveWireOutputTokens` always sends a bound (override, else `min(known limit, DEFAULT_OUTPUT_WIRE_CAP = 32000)`), and the manager sends it capped by the reserve (half the context window) so prompt + `max_tokens` fits small-context servers such as vLLM. Both are resolved by `LimitsService`. `mcpOutput.maxTokens` (default `DEFAULT_MCP_OUTPUT_TOKENS` 25000) caps MCP tool output; `compaction` numeric knobs are optional (undefined = auto-resolved by `resolveCompactionSettings`). `normalizeProvider` preserves `providerType` so provider-specific LLM handling (e.g. DeepSeek reasoning_content echo) and the settings UI survive a reload. `sampling` (per-model overrides) is normalized on load and survives a settings save. |
| `session.ts` | `SessionStore`: persists sessions + transcript items to per-session `.jsonl` files via `SessionFileStore` (see `session-file-store.ts`); `flush()` forces debounced index writes; create/list/switch/delete/rename; title inference (`titleFrom` strips base64 image data URLs and markdown image syntax so only actual text is used for session titles). Also carries the deterministic idempotency helpers `hasMessage` / `appendMessageIfMissing` (dedup by message id, used for delegation/recovery payloads) and `ensure(id, agentId, projectPath)` so a delegated turn can target a concrete session that does not exist yet. |
| `session-records.ts` | Pure JSONL records layer: `sessionToRecords`/`serializeSessionJsonl`/`parseSessionJsonl` convert a `StoredSession` to/from per-session JSONL text (`meta` + `message`/`tool` transcripts with linear `parentUuid`, plus latest-wins `title`/`todos`/`usage` records). `parseSessionJsonl` coerces a corrupt `todos` record (non-array) to `[]` so a damaged file cannot propagate a bad value into the renderer. No filesystem. |
| `session-file-store.ts` | `SessionFileStore`: read side of per-session JSONL storage. Locates files under `projects/<encoded>/<id>.jsonl`, lazily parses a session on demand (`get(id)`), and maintains an in-memory index of summaries loaded from `sessions-index.json` or rebuilt by scanning `projects/` (`list()`); corrupt index files are parked as `.corrupt` and rebuilt. Index write is debounced with `flush()`. Write path: `create`/`rewrite` do a full atomic write + cache + reindex, `append` appends one JSON line per record, `reindex` upserts the index summary, `remove` deletes the file and drops it from cache + index. `migrateLegacy()` runs the one-time `migrateSessions` migration (best-effort) to move a legacy `sessions.json` into per-session jsonl files — called from the app-ready chain in `index.ts` *after* the v0.37 reset, so the reset's `sessions.json` delete is not undone by a migration that would back the file up first. |
| `session-migrate.ts` | `migrateSessions(rootDir)`: one-time, idempotent migration from the legacy `sessions.json` array to per-session jsonl files. Flag-guarded by `.sessions-migrated-v1`; normalizes legacy entries (falls back to id for `agentId`, derives title from the first user message, falls back to `updatedAt` for `createdAt`), writes `projects/<encoded>/<id>.jsonl` + `sessions-index.json` via `writeFileAtomic`, and renames `sessions.json` → `sessions.json.migrated-bak` (never deletes). |
| `run-context.ts` | `AgentRunContext` (fixed per-turn identity), `AgentTurnResult`, `DelegatedTurnInput`, `DelegationResultInput` — the shared contracts between the manager's fixed-session runs and the `SessionDelegationService`. |
| `permission.ts` | Permission rules (allow/ask/deny) + matcher used by `decidePermission`; `ToolPermissionContext` + `decide` gate every tool call, and `deriveSubagentContext` narrows the parent's context for a subagent (deny > ask > allow, no prompting in background). |
| `subagent-roles.ts` | Subagent role discovery: `.meow/agents/*.md` (project) → user dir → built-ins, first-wins by name; frontmatter (`name`, `description`, `tools`, `model`, `deny`, `ask`) can only narrow permissions — there is no `allow` key. |
| `commands.ts` | Slash commands: built-ins (init/review/Superpowers skills) + user store (`commands.json`) + `resolveCommand`/`expandReferences`-aware templates. |
| `references.ts` | `expandReferences`: expands `@path` / `@"path with space"` mentions into file contents appended to the prompt. |
| `snapshot.ts` | `SnapshotStore`: per-turn file snapshots for undo/redo. |
| `saved-permissions.ts` | Persists "always allow" tool permissions (`permissions.json`). |
| `compact.ts` | Context compaction: `usableContextTokens` (buffer + output reserve), `resolveCompactionSettings` (auto-scales buffer/keepTokens/toolOutputMaxChars by ratio of context window with floors; `keepTokens` clamped to half usable), `truncateToolOutput`, `fitHeadToBudget` (keeps the summary prompt inside the window), `hardTruncate` (last-resort shrink when LLM compaction cannot help). |
| `limits.ts` | `LimitsService.resolveLimits` merges override → learned → live `/models` → catalog → 128k default into `{ context, output: number \| null }` (output null = no source knows the cap; `resolveWireOutputTokens` still sends `DEFAULT_OUTPUT_WIRE_CAP`); `parseLiveModelsInfo`, `matchModel`, `classifyContextOverflowError`, `parseContextLimitFromError`; live fetch is background, cached per `baseUrl\|apiKey` with `LIVE_MODELS_TTL_MS`. |

| `truncation.ts` | `TruncationStore`: truncation state per session. |
| `usage.ts` | `calcCost` / `EMPTY_USAGE` / price-based cost accounting. |
| `token.ts` | Token estimation/counting helpers (`estimateTokens`, `estimateUsage`, `charsForTokens`); inline image data URLs are charged a flat cost, not their base64 length. |
| `apply-patch.ts` | Unified-diff parser + applier (the `apply-patch` tool backend). |
| `plugin.ts` | Loads user tools from `userData/tools`. |
| `skill.ts` | Collects skills (builtin + user) into `skillListText` for the system prompt. |
| `instructions.ts` | Loads `AGENTS.md`-style instructions into the system prompt. |
| `prompt.ts` | `buildSystemPrompt` assembles the labeled harness prompt (identity, project instructions, memory, skills, mode, precedence note); `buildTurnReminder` renders the per-turn `<system-reminder>` block (env snapshot + memory index, and an optional bounded `env.peers` session list distinguishing `delegate_session` from the ephemeral `task` tool). |
| `env.ts` | `snapshotEnvironment` captures platform/shell/cwd/date/git once per run; `gitFreshnessReminder` returns fresh git state for tool-result reminders. `SessionPeer` (`agentId`/`name`/`mode`/`state`) is the per-turn reminder shape for delegatable session peers; `EnvSnapshot.peers` carries the optional bounded peer list. |
| `memory.ts` | Per-project `.meow/memory/` store: `loadMemoryIndex` (≤ 200 lines, pass-through as data), `memoryRulesText` (system-prompt rules), `parseMemoryFile`, `isMemoryPath`. |

## Conventions

- All agent logic lives in the **main process**; the renderer only sees `ChatEvent`s over IPC.
- Tests use a **model stub** (`createLlm` fake) — never hit a real LLM API (see `tests/unit/agent-loop.test.ts`).
- New tools: implement in `tools/`, register in `tools/registry.ts`, add permission default in `config.ts`.
- Session transcript items are the single source of truth for what the LLM sees (`message.ts` rebuilds prompts from them).
- **Hooks tighten, never loosen.** A `PreToolUse` hook may deny a call, rewrite its input, or waive a permission prompt, but it can never override a config deny (`loop.ts` applies the hook decision around `decidePermission`). A failed or timed-out hook yields *no* decision, so broken policy never blocks work.
- Hooks run in subagents too — same cwd, same merged config — and `LoopDeps.hooks` is a **function**, resolved once per run like `system`, so editing a hooks file lands on the next turn without a reload.
- Hooks stay out of the transcript: they are policy machinery, not conversation. What the model sees is only a blocked call's error, a replaced tool output, or appended context.
